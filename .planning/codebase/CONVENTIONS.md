# Coding Conventions

**Analysis Date:** 2026-05-25

## Python Style (Backend)

**Formatter/Linter:** Ruff — config at `backend/ruff.toml`

**Key settings:**
- `line-length = 99` (wider than Black default 88)
- `target-version = "py312"`
- `quote-style = "double"` — all strings use double quotes
- `indent-style = "space"` (4 spaces)

**Enabled rule sets:** E/W (pycodestyle), F (pyflakes), I (isort), B (bugbear), C4 (comprehensions), UP (pyupgrade), DJ (django), N (pep8-naming), SIM (simplify), TID (tidy-imports)

**Per-file ignores:**
- `*/settings/*.py` — F405, F403, N802 (wildcard imports allowed)
- `*/migrations/*.py` — E501, N806 (autogenerated, not hand-styled)
- `*/tests/*.py` — N802, S101 (asserts allowed, method names may deviate)

**Type hints:** Required on all public functions. Example from `backend/apps/optimizer/services/solver.py`:
```python
def solve_route(
    distance_matrix: list[list[float]],
    time_matrix: list[list[float]],
    price_savings: list[float],
    weights: dict[str, float],
    max_stops: int,
) -> list[int]:
```

**Docstrings:** Google style in Spanish, on all public classes and functions:
```python
class Category(models.Model):
    """Categoría de producto con jerarquía de 2 niveles máximo."""
```

**Import order (isort profile):**
1. `from __future__ import annotations`
2. stdlib
3. third-party (`django`, `rest_framework`, `celery`)
4. first-party (`apps`, `config`)

## Django Model Conventions

**Field naming:** `snake_case`. Field `verbose_name` always in Spanish.

**TextChoices:** Inner class pattern:
```python
class Role(models.TextChoices):
    CONSUMER = "consumer", "Consumidor"
    BUSINESS = "business", "Comercio"
    ADMIN = "admin", "Administrador"
```

**Nullable fields:** Always `null=True, blank=True` together. `DJ001` suppressed globally.

**Meta class:** Always include `verbose_name`, `verbose_name_plural`, `ordering` where relevant:
```python
class Meta:
    verbose_name = "Categoría"
    verbose_name_plural = "Categorías"
    ordering = ["name"]
```

**`__str__`:** Always typed `-> str`, returns human-readable label.

**`save()` overrides:** Used for auto-derived fields (slug, normalized_name). Always call `super().save()` last.

**`clean()` overrides:** Used for cross-field business rule validation raising `ValidationError`.

## API Response Format

All DRF views respond through `bargain_exception_handler` in `backend/apps/core/exceptions.py`.

**Success response:**
```json
{ "success": true, "data": { ... } }
```

**Error response:**
```json
{
  "success": false,
  "error": {
    "code": "STORE_NOT_FOUND",
    "message": "No se encontraron tiendas en el radio especificado",
    "details": {}
  }
}
```

Error codes are `UPPER_SNAKE_CASE`. Custom domain exceptions extend `BargainAPIException` in `backend/apps/core/exceptions.py`. Available exceptions: `StoreNotFoundError`, `ProductNotFoundError`, `PriceExpiredError`, `OptimizationError`, `InsufficientStoresError`, `OCRProcessingError`, `AssistantError`, `SubscriptionRequiredError`, `RateLimitExceededError`, `BusinessNotVerifiedError`, `PromotionConflictError`.

## TypeScript/JavaScript Style (Frontend)

**Linter:** ESLint 9 flat config at `frontend/eslint.config.mjs` (extends `eslint-config-expo/flat.js`)

**Formatter:** Prettier — `printWidth: 100, singleQuote: true`. Run via `npm run format`.

**Component pattern:** Functional components only with hooks. Named exports for all screens and components:
```typescript
export const LoginScreen: React.FC = () => { ... };
export const ProductCard: React.FC<ProductCardProps> = ({ product, onPress }) => { ... };
```

**Props interfaces:** Defined above the component with `Props` suffix:
```typescript
interface ProductCardProps {
  product: Product;
  onPress: (id: string) => void;
}
```

**Naming:**
- Components/screens: `PascalCase` — files match: `LoginScreen.tsx`, `ProductCard.tsx`
- Functions/variables/hooks: `camelCase`
- Zustand stores: `use[Name]Store` — `useAuthStore`, `useListStore`, `useNotificationStore`
- Services: `[domain]Service` singleton objects — `authService`, `storeService`, `listService`
- Types/interfaces: `PascalCase`, defined in `frontend/src/types/domain.ts`

**Path aliases:** Use `@/` prefix (mapped to `src/`) via `babel-plugin-module-resolver`:
```typescript
import { colors, spacing } from "@/theme";
import { useAuthStore } from "@/store/authStore";
```

**Service layer rule:** Screens never call `apiClient` directly. All HTTP calls go through domain service objects in `frontend/src/api/`.

**Async errors:** `try/catch` with `setState(error)` for inline error display. Do not use `Alert.alert()` for user-facing errors.

## Git Conventions

**Branch naming:** `feature/XX-descripcion`, `fix/XX-descripcion`, `docs/XX-descripcion` — always branch from `develop`.

**Commit format:** Conventional Commits in Spanish with task ID appended:
```
feat(optimizer): implementar algoritmo de ruta ponderada (F4-21)
fix(scraping): corregir parser de precios Mercadona (F3-05)
test(prices): añadir tests unitarios del servicio de precios (F4-10)
```

**Valid types:** `feat`, `fix`, `docs`, `test`, `refactor`, `chore`

**PRs:** Always target `develop`. Require description and checklist.

## Comments and Documentation

**Python module docstrings:** Triple-quoted string at module top listing covered models/logic.

**TypeScript JSDoc:** Above service functions and complex utilities:
```typescript
/**
 * Normaliza la respuesta del backend (/auth/profile/me/) al tipo UserProfile.
 */
function normalizeProfile(raw: UserProfile): UserProfile { ... }
```

**Test section dividers:** ASCII dividers separate mocks/imports/describe blocks in test files:
```typescript
// ─── Mocks ────────────────────────────────────────────────────────────────────
// ─── Imports (after mocks) ────────────────────────────────────────────────────
```

**Language:** All comments and docstrings are in Spanish throughout the codebase.

## Logging

**Backend:** `structlog` used project-wide. Structured key=value style, not f-strings:
```python
logger = structlog.get_logger(__name__)
logger.warning("solve_route_insufficient_nodes", n=n)
logger.error("ortools_not_installed")
```

**Frontend:** No logging library — `console.*` for development; production errors go to Sentry.
