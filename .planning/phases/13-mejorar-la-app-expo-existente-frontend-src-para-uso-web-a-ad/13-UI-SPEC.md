# Phase 13 — UI Design Contract

> Visual and interaction contract for Phase 13: enhancing the existing Expo app (`frontend/src`)
> for web use. Generated by gsd-ui-researcher. This is NOT a greenfield design — all tokens are
> taken directly from the existing `frontend/src/theme/` design system.

---

| Property | Value |
|----------|-------|

## Responsive Breakpoints

These are NEW contracts for Phase 13. Apply via `useWindowDimensions` inside each screen.

| Name | Min-width | Layout mode |
|------|-----------|-------------|
| `mobile` | 0px | Single column, full mobile layout (unchanged) |
| `tablet` | 768px | Two-column starts; master-detail for lists/map cluster |
| `desktop` | 1024px | Full master-detail, wider grids (3–4 col), sidebar-like panels |

Implementation: add a `useBreakpoint()` hook in `frontend/src/hooks/useBreakpoint.ts` that returns
`'mobile' | 'tablet' | 'desktop'` from `useWindowDimensions`. Use `.web.tsx` files ONLY when
divergence is structurally large (following `MapScreen.web.tsx` precedent). For layout-only
differences use the hook inline.

## Spacing Scale

Source: `frontend/src/theme/spacing.ts` — 8pt grid, all multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| `spacing.xs` | 4px | Icon gaps, badge padding, fine adjustments |
| `spacing.sm` | 8px | Compact element spacing, inline gaps |
| `spacing.md` | 16px | Default component padding, row padding |
| `spacing.lg` | 24px | Section padding, group separations |
| `spacing.xl` | 32px | Layout column gaps, block separations |
| `spacing.xxl` | 48px | Screen header spacing, generous section breaks |
| `spacing.xxxl` | 64px | Page-level heroic spacing (onboarding-scale) |

**Web-specific exceptions:**
- Master-detail divider gutter: `spacing.xl` (32px) fixed column gap on desktop.
- Tab bar horizontal padding on desktop (≥1024px): `spacing.lg` (24px) side padding per tab item.
- Tooltip padding: `spacing.xs` vertical + `spacing.sm` horizontal (4px / 8px).
- Touch targets on web (mouse context): minimum 36px tall (can relax 44px mobile minimum to 36px
  since pointer precision is higher). Keep 44px on tablet.

## Typography

**Inheritance rule:** All existing screens inherit their typography from the pre-existing
`textStyles.*` composites in `frontend/src/theme/typography.ts`. Those composites are NOT
re-declared here — Phase 13 reuses them as-is without introducing new sizes. Only the NEW
web-specific affordances introduced in this phase are declared below.

| Role | textStyles key | Size (px) | Weight | Line Height ratio | Usage in Phase 13 |
|------|---------------|-----------|--------|-------------------|-------------------|
| Tooltip / keyboard-shortcut caption | `textStyles.caption` | 12px (`fontSize.xs`) | 400 (regular) | 1.55 (`lineHeight.normal`) | WebTooltip label text, keyboard-shortcut badge inside tooltip (e.g. "⌘K"), empty-state sub-copy |
| Export / share button label | `textStyles.button` | 16px (`fontSize.md`) | 600 (semibold) | 1.35 (`lineHeight.snug`) | "Exportar lista", "Exportar ruta", "Exportar comparativa", "Compartir enlace" button labels |
| MasterDetailLayout panel header | `textStyles.heading3` | 20px (`fontSize.xl`) | 600 (semibold) | 1.35 (`lineHeight.snug`) | Master-pane section title on desktop (e.g. "Mis listas", "Tiendas cercanas") |

Declared: 3 distinct font sizes (12, 16, 20 px), 2 distinct font weights (400, 600).

**Web font note:** On web, `fontFamily` resolves to the Google Fonts variants (not `undefined`).
The theme handles this automatically via `Platform.OS === 'ios'` branching.

## Color

Source: `frontend/src/theme/colors.ts` — "Mercado Mediterráneo Digital" palette. Do not introduce
any new hex values in Phase 13.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `colors.background` | `#FAFAF7` | Root screen background, page canvas |
| Secondary (30%) | `colors.surface` + `colors.surfaceVariant` | `#FDF6EC` / `#F2E3D1` | Cards, detail panels, master panel sidebar, tab bar, modals |
| Accent (10%) | `colors.primary` | `#E8541A` | See reserved-for list below |
| Destructive | `colors.error` | `#C0392B` | Delete confirmations only |
| Success semantic | `colors.success` | `#3A7D44` | Savings badges, optimal route indicator, checked items |
| Warning semantic | `colors.warning` | `#D4850A` | Price-expiry warnings, stale-data alerts |
| Info semantic | `colors.info` | `#1A6B8A` | Tooltips background, neutral info callouts |

**Accent (`#E8541A`) reserved for:**
1. Primary CTA buttons (Añadir ítem, Crear lista, Optimizar ruta, Enviar mensaje)
2. Active tab indicator (bottom tab bar active state)
3. Selected item / selected store highlight border
4. Focus ring on web (2px solid `colors.primary` with 2px offset)
5. "Buscar en esta zona" floating pill label text
6. Hover state background tint uses `colors.primaryTint` (`#FCE7DD`), not the accent itself

**`colors.accent` (#F5C842, "Amarillo Azulejo"):** This token exists in `frontend/src/theme/colors.ts`
but is NOT used in any new Phase 13 component or affordance. Existing screens may retain any
current usages of `colors.accent` — do not strip them. Do not introduce new usages of
`colors.accent` in Phase 13 work.

**Hover contract (web only, pointer device):**
- Touchable rows / cards: background transitions to `colors.primaryTint` (`#FCE7DD`) on hover.
- Icon-only buttons: background transitions to `colors.surfaceVariant` on hover.
- Destructive actions: background transitions to `colors.errorBg` (`#FBEAEA`) on hover.
- Transition: `background-color 150ms ease` via inline `style` or `StyleSheet` `hovered` state
  (use react-native-web's `onMouseEnter`/`onMouseLeave` or Pressable's `hovered` prop).

**Focus ring contract (web keyboard navigation):**
- All focusable elements: 2px solid `colors.primary` (#E8541A) outline, 2px offset.
- Applied via `outlineColor` / `outlineWidth` / `outlineOffset` on web (react-native-web supports these).
- Never remove focus ring without replacement; `outline: 'none'` is forbidden unless a custom focus
  indicator is present.

## Component Inventory for Phase 13

These are the NEW components and patterns the executor must create or extend. All use existing
theme tokens.

### New: `useBreakpoint` hook
- Path: `frontend/src/hooks/useBreakpoint.ts`
- Returns `'mobile' | 'tablet' | 'desktop'`
- Uses `useWindowDimensions`; thresholds: 768 / 1024

### New: `MasterDetailLayout` component
- Path: `frontend/src/components/ui/MasterDetailLayout.tsx`
- Props: `masterPane: ReactNode`, `detailPane: ReactNode | null`, `breakpoint: 'mobile'|'tablet'|'desktop'`
- Mobile/tablet: renders `masterPane` only (detail is a separate navigation push).
- Desktop: renders split view — master left (fixed 360px), detail right (flex: 1).
- Master pane background: `colors.surface`; divider: 1px `colors.border`.

### New: `WebTooltip` component
- Path: `frontend/src/components/ui/WebTooltip.tsx`
- Web-only: wraps children, shows `label` text on hover after 400ms delay.
- Background: `colors.info` (#1A6B8A), text: `colors.white`, `textStyles.caption` size.
- Padding: 4px vertical / 8px horizontal (`spacing.xs` / `spacing.sm`).
- Border radius: `borderRadius.sm` (6px).
- Not rendered on mobile (returns children unwrapped).

### Existing: `BottomTabBar` — web adaptation
- On desktop (≥1024px): increase tab item horizontal padding to `spacing.lg` (24px), increase icon
  size from 24px to 26px, keep label always visible (already the default).
- Tab bar max-width: 900px centered on screens wider than 900px.
- No structural navigation changes (D-12).

### Existing: `AppModal` — no changes needed. Already renders correctly on web.

## Interaction Contracts

### D-05: Wide responsive layout / master-detail

**Lists cluster** (ListsScreen, ListDetailScreen, TemplatesScreen):
- Desktop: `MasterDetailLayout` — list of shopping lists on left (360px master), list detail on
  right (flex: 1). Selecting a list from the left updates the detail pane without navigation push.
- Tablet: single column with wider cards (max-width 600px centered).
- Product/template grid in TemplatesScreen: 1 col mobile → 2 col tablet → 3 col desktop.

**Map cluster** (MapScreen.web.tsx, StoreProfileScreen):
- MapScreen.web.tsx already uses a bottom panel. Desktop: convert bottom panel to a right-side
  panel (320px wide, full height). Map fills remaining width.
- StoreProfileScreen desktop: two-column — store info left (50%), price history / products right (50%).

**Catalog/Prices cluster** (HomeScreen, ProductsCatalogScreen, PriceCompareScreen):
- ProductsCatalogScreen: 2 col mobile-wide / 3 col tablet / 4 col desktop for product grid.
- PriceCompareScreen: comparison table stays full-width but gains sticky headers on web.
- HomeScreen: hero section max-width 800px, centered; quick-action buttons in a horizontal row on
  desktop instead of vertical stack.

**Assistant cluster** (AssistantScreen):
- Desktop: chat bubbles max-width 720px, centered. Input bar stays at bottom, max-width 720px.

**Notifications / PriceAlerts** (NotificationScreen, PriceAlertsScreen):
- Desktop: list max-width 680px, centered. No master-detail needed.

### D-06: Mouse and keyboard interactions

**Hover states:** See Color section — `colors.primaryTint` for rows/cards, `colors.surfaceVariant`
for icon buttons, `colors.errorBg` for destructive targets.

**Focus ring:** 2px solid `colors.primary`, 2px offset. Apply to all `TouchableOpacity` /
`Pressable` elements on web via `focusStyle` or `outlineColor`.

**Keyboard shortcuts (web only):**
- `Enter` key on text input: submit add-item form (ListDetailScreen).
- `Escape` key: close any open `AppModal` or dismiss focus from search inputs.
- `Ctrl+K` / `Cmd+K`: focus the search bar when present (ProductsCatalogScreen, HomeScreen).
- Keyboard shortcut labels: shown in `WebTooltip` as grey caption text, e.g. "⌘K".

**Tooltips:** Use `WebTooltip` component for all icon-only buttons (delete, edit, share, export,
copy). Tooltip text is the `accessibilityLabel` of the action.

### D-07: Web convenience features

**Drag-drop reorder** (ListDetailScreen, ListsScreen):
- List items in ListDetailScreen: drag-to-reorder using `react-native-draggable-flatlist` (already
  in the Expo ecosystem) or a web-only drag implementation via HTML5 drag events in a `.web.tsx`
  variant. Confirm order change optimistically; persist via API PATCH.
- Visual indicator during drag: item lifts with `shadows.elevated`, background `colors.surface`.

**Export / download:**
- RouteScreen: "Exportar ruta" button → downloads a plain text `.txt` file with the ordered stop
  list and estimated cost/distance. Use `navigator.clipboard` for copy variant.
- ListDetailScreen: "Exportar lista" → downloads `.txt` with item names and quantities.
- PriceCompareScreen: "Exportar comparativa" → downloads `.csv` with product name, store, price,
  unit price columns.
- Export file naming convention: `bargain-{type}-{YYYY-MM-DD}.{ext}`.
  - Examples: `bargain-ruta-2026-06-01.txt`, `bargain-lista-2026-06-01.txt`,
    `bargain-comparativa-2026-06-01.csv`.
- Export button label: per-screen noun-bearing label with Ionicons `download-outline` icon (24px):
  - RouteScreen: "Exportar ruta"
  - ListDetailScreen: "Exportar lista"
  - PriceCompareScreen: "Exportar comparativa"
- Only shown on web (`Platform.OS === 'web'`).

**Copy to clipboard:**
- PriceAlertsScreen: copy alert summary (product name + threshold) — Ionicons `copy-outline` button.
- AssistantScreen: copy individual assistant message — `copy-outline` icon appears on hover.
- StoreProfileScreen: copy store address — `copy-outline` inline button after the address field.
- Visual feedback: button transitions to `colors.success` for 1500ms then reverts (no toast needed).

## Implementation Constraints (Non-Negotiable)

1. All spacing values MUST use `spacing.*` tokens. No magic numbers.
2. All colors MUST use `colors.*` tokens. No inline hex values.
3. All typography MUST use `textStyles.*` or `fontSize.*` + `fontFamilies.*` composites from `@/theme`.
4. No new screens. No navigation tree changes beyond adding `linking` config (D-11, D-12).
5. `frontend/web/` (Vite + Ant Design) must not be touched (D-02).
6. Mobile layout must be pixel-identical to pre-Phase-13 behavior. Responsive changes activate
   only at `≥768px`.
7. `Platform.OS === 'web'` guard required for all web-only features (export, clipboard, URL share,
   tooltips, keyboard shortcuts).
8. `.web.tsx` files only for structurally large layout divergence (following MapScreen.web.tsx
   precedent). Use the `useBreakpoint` hook for layout-only differences.
9. `Ionicons` is the only icon set. No new icon library additions.
10. `accessibilityRole`, `accessibilityLabel` are required on all new interactive elements.
